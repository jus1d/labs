# 2. Проектирование системы

Проектирование — это процесс создания архитектуры и структуры программного продукта. Основная цель проектирования — создать систему, которая будет легко поддерживаться, расширяться и модифицироваться.

Проектирование включает в себя следующие задачи:

- выбор архитектурного стиля;
- определение модулей и их взаимодействий;
- разработка интерфейсов и протоколов взаимодействия компонентов.

## 2.1. Выбор и обоснование архитектуры системы

Архитектура программного обеспечения — совокупность важнейших решений об организации программной системы. Архитектура включает выбор структурных элементов и их интерфейсов, а также описание их поведения в рамках взаимодействия между собой.

### 2.1.1. Виды архитектур

Рассмотрим наиболее популярные виды архитектур:
1. Монолитная архитектура — все компоненты системы объединены в одно приложение, которое выполняется как единый процесс. Характеризуется простотой разработки и развёртывания, однако плохо масштабируется при увеличении сложности.
2. Микросервисная архитектура — приложение разбито на множество мелких сервисов, каждый из которых выполняет свою функцию и может разрабатываться, развёртываться и масштабироваться независимо.
3. Сервисно-ориентированная архитектура — приложение строится на основе взаимодействия сервисов через стандартизированные интерфейсы, такие как SOAP (Simple Object Access Protocol) или REST (Representational State Transfer). Включает более крупные и сложные сервисы по сравнению с микросервисами.
4. Архитектура клиент-сервер — приложение разделено на клиентскую часть, которая взаимодействует с пользователем, и серверную часть, которая обрабатывает запросы и управляет данными.
5. Трёхуровневая архитектура — система делится на три логических уровня: уровень представления, уровень бизнес-логики и уровень данных.
6. Событийно-ориентированная архитектура — приложение реагирует на события. Компоненты системы обрабатывают события асинхронно, взаимодействуя через обмен сообщениями.

### 2.1.2. Клиент-серверная архитектура

Рассмотренные выше архитектурные подходы показывают разнообразие способов организации программных систем. Одним из наиболее широко применяемых решений является клиент-серверная архитектура.

Клиент-серверная архитектура — это система распределения, в которой одни устройства обращаются к другим для получения необходимой информации или выполнения определённых задач. Первые из них называются клиентами, вторые — серверами.

Клиент — это устройство на стороне пользователя, которое отправляет запрос к серверу для предоставления информации или выполнения определённых действий.

Сервер — это более мощный компьютер или оборудование, предназначенное для решения определённых задач по выполнению программного кода, сервисных функций по запросу клиентов, предоставления пользователям доступа к определённым ресурсам и хранения информации.

Различают двухзвенную и трёхзвенную клиент-серверные архитектуры. Двухзвенная архитектура распределяет три базовые компоненты между двумя узлами (клиентом и сервером) и используется в системах, где сервер отвечает на клиентские запросы напрямую и в полном объёме, используя только собственные ресурсы.

Трёхзвенная клиент-серверная архитектура — это модель, в которой приложение разделено на три логических уровня: презентационный, логический и уровень данных. Это разделение позволяет улучшить управляемость, масштабируемость и безопасность системы.

### 2.1.3. Определение веб-приложения

Веб-приложение — это клиент-серверное приложение, в котором клиент взаимодействует с сервером через браузер. Веб-приложения позволяют пользователям не только просматривать информацию, но и вводить данные, влияя на состояние системы и бизнес-логику на сервере.

### 2.1.4. Протоколы передачи данных

Для успешного взаимодействия между клиентом и сервером необходимо определить правила обмена данными. Эти правила задаются сетевыми протоколами, которые обеспечивают стандартизированное взаимодействие и передачу информации.

Протокол в программировании — это набор правил и соглашений, которые определяют способ обмена данными между устройствами и программами в сети.

Различают множество различных протоколов, относящихся к различным уровням в стеке TCP/IP. Некоторыми из самых известных являются:

- IP (Internet Protocol) — основной сетевой протокол, обеспечивающий адресацию и маршрутизацию данных в сети. Он определяет, куда отправлять пакеты, но не гарантирует их доставку, порядок или целостность.
- TCP (Transmission Control Protocol) — транспортный протокол, работающий поверх IP и обеспечивающий надёжную передачу данных. Он гарантирует доставку информации, упорядоченность пакетов, контроль ошибок и управление потоком.
- UDP (User Datagram Protocol) — обеспечивает передачу данных, не создавая соединения. Этот протокол считается менее надёжным, но имеет более высокую скорость доставки данных по сравнению с TCP.
- HTTP (HyperText Transfer Protocol) — протокол передачи данных в интернете, основанный на схеме «запрос-ответ»: клиент отправляет HTTP-запрос к серверу, который возвращает ответ с запрошенными данными и статусом. Протокол не сохраняет состояние, использует URL для адресации ресурсов и работает поверх TCP/IP.

### 2.1.5. Типы клиентов

Для двухуровневой архитектуры характерно два типа клиентов:

- «Тонкий» клиент — клиентское приложение, которое минимизирует логику и функциональность на стороне пользователя, делегируя большинство задач серверу.
- «Толстый» клиент — клиентское приложение, которое содержит значительную часть логики и функциональности непосредственно на стороне пользователя и обладает значительной автономностью.

### 2.1.6. Выводы

В разрабатываемой системе «Игра «Кубик Рубика» будет реализована двухзвенная клиент-серверная архитектура в технологии «толстый» клиент. Сервер (Ubuntu 22.04 и выше) выполняет роль веб-сервера: принимает запросы от браузера и отдаёт статические файлы приложения (HTML, CSS, JavaScript). Вся бизнес-логика — модель кубика, алгоритмы сборки, управление состоянием — исполняется непосредственно в браузере пользователя (Windows 10 и выше, Google Chrome 86+ или Firefox 83+). Реализация ведётся на языке JavaScript с использованием библиотеки React.

## 2.2. Структурная схема системы

При разработке сложных программных и технических решений применяется методология структурного проектирования, основанная на принципах декомпозиции и иерархической организации компонентов. Система в данном контексте представляет собой совокупность взаимосвязанных элементов, образующих целостность и единство, а также функционирующих для достижения общей цели.

Одним из ключевых подходов структурного проектирования является алгоритмическая декомпозиция, предполагающая разбиение системы на иерархически организованные модули по принципу «часть-целое». При этом внутренняя связанность элементов внутри подсистем должна быть сильнее, чем связи между самими подсистемами, что способствует улучшению модульности и управляемости системы.

Серверная часть системы выполняет единственную функцию — обслуживание статических файлов приложения. При обращении браузера к серверу тот возвращает файлы React-приложения, после чего всё взаимодействие происходит на стороне клиента без дополнительных обращений к серверу.

В состав клиентской части системы входят следующие подсистемы:

1. Подсистема визуализации кубика — отвечает за трёхмерное отображение кубика Рубика, рендеринг граней и элементов, анимацию вращений с учётом выбранного скоростного режима, а также управление камерой и отрисовку интерфейсных элементов.

2. Подсистема игровой логики — содержит модель состояния кубика (позиции и ориентации всех 26 подвижных элементов), реализует операции вращения граней согласно нотации Сингмастера, обеспечивает проверку корректности состояния и определение условия победы.

3. Подсистема автоматической сборки — реализует два алгоритма автоматической сборки (метод послойной сборки LBL и метод Фридриха CFOP), формирует последовательность ходов для перехода из текущего состояния в собранное за время не более 5 секунд.

4. Подсистема случайной разборки — генерирует случайную последовательность ходов для перевода кубика из собранного состояния в произвольное.

5. Подсистема цветовых палитр — обеспечивает применение одной из 5 предустановленных цветовых палитр к оформлению кубика, а также поддерживает ручное изменение цветов пользователем. Палитры хранятся в виде файлов конфигурации, загружаемых при инициализации приложения.

6. Справочная подсистема — предоставляет пользователю вспомогательную информацию по работе с системой: описание нотации, управляющих элементов и режимов работы.

Вся информация, необходимая для работы системы, хранится в оперативной памяти браузера в течение сеанса работы.
